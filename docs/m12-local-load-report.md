# M12 local resilience-load report

Measured on 2026-08-27 with the isolated Compose verification environment authorized by ADR-021. This is a local emulator measurement, not a hosted capacity claim.

## Environment

| Field                     | Measurement                                                                              |
| ------------------------- | ---------------------------------------------------------------------------------------- |
| Workload                  | HMAC-signed JSON event, approximately 250-300 UTF-8 bytes before HTTP headers            |
| Executor                  | k6 0.57.0 `constant-arrival-rate`, 10-second warm-up and 60-second measured interval     |
| Docker / Node             | Docker Engine 27.4.0 / Node 24.11.1                                                      |
| Local VM                  | Colima ARM64, 4 CPUs, 6 GiB configured memory                                            |
| Persistence               | DynamoDB Local 2.5.2, disposable in-memory shared database                               |
| Destination setup         | Alpha and Beta mock destinations; scenario-specific disable, timeout, 503, and 429 modes |
| Worker concurrency        | One Compose container each for outbox, reconciler, router, and delivery workers          |
| Queue depth, primary test | Routing 0 to 263 visible plus 1 in flight; delivery 0 to 0                               |

The concurrent-search probe collected 637 samples with 31.62 ms p95, below its 500 ms target. The primary benchmark met every gate: no dropped iterations, at least 100 successful acceptances per second, under 1% final request failure, and ingestion p95 below 300 ms. Its client recorded 20 bounded transport retries; the workload counts only the final idempotent acceptance outcome.

Machine-readable inputs are intentionally ignored at `load-artifacts/` and are regenerated by `pnpm local:verify:deep`; they are not retained in the working tree. The restore drill separately measured 51 core and 10 audit records, 782 ms observed RPO, and 22,662 ms observed RTO.

## Emulator limitations

DynamoDB Local and ElasticMQ do not model managed DynamoDB throughput, autoscaling, SQS fleet behavior, Lambda concurrency, or network path latency. The mock partners run on the same local VM. The result establishes the stated controlled local acceptance gate only; hosted performance remains optional under ADR-021.
